The grid

Each run trains one model on one SID map and evaluates it once on the test cohort. sidlens reads the runs in place and writes nothing into the OneDiffRec work root.

CatalogNative mapsZCR twinsMapsRuns per mapTest users
Industrial_and_Scientific272148AR and DiffGRM × next-item and next-twoall 6,297
Office271845AR and DiffGRM × next-item and next-twosample of 6,297 for model runs; all for saved-list analyses

Models: Qwen2.5-1.5B SFT for AR (28 layers), DiffGRM (1 encoder and 4 decoder layers, width 256) for diffusion. Weight states: every run's best checkpoint; AR runs also keep epochs 0.5 and 1.5 (186 next-item states), and DiffGRM runs keep per-epoch snapshots (about 190 next-item states).

Two scripts start everything. run_best_state.sh runs every experiment on every map at the best state. run_full.sh adds a cheap set at every intermediate state: AR exp3 Part A and exp4 Part R (test split), and DiffGRM exp7. Results land in results_remote/<group>/<experiment>/<dataset>/<task>/<paradigm>/<map>/<state>/.

Checks before a result counts

Every cell runs these checks first and stops if one fails. A stopped cell is marked failed and rerun into a new folder; nothing is overwritten.

The experiments

The experiments are listed in run order. "Runs" counts grid runs at the best state. The minutes per run are A100 estimates; the Time section gives their basis.

AR: controlled interventions

exp3 · history patching

controlled/exp3_ar_history_patching

How much does each history item matter, and where in the network does its information sit?

What it does
Part A replaces one history item at each recency (most recent first) with a catalog item sharing the first m digits, and scores the golden target digits by teacher forcing. Part B patches the residual stream at every layer from the clean run into the run where the most recent item was replaced, at that item's tokens, the separator and the target positions.
Runs on
93 AR next-item runs; Part A also at both intermediate AR states
Output
Change in golden digit log-probability by recency and shared prefix; the share of the effect each patch restores, by layer and position
Time
48 min per run (A 7, B 41)

exp4 · prefix-matched copying

controlled/exp4_ar_copy_circuit

Does the model copy digit d from history items that already match the target's first d digits, and through which attention edges?

What it does
R: change digit d of a history item and compare items that match the target prefix with items that do not. K: remove the single attention edge from the readout of digit d to that item's digit-d token, in early layers, late layers and all layers, against a control edge. H: screen every head on half the users, then test the top 5 on the other half.
Runs on
93 AR next-item runs, test and validation splits; Part R also at both intermediate states (test)
Output
Copy effect in nats by digit; edge-knockout effect by layer range; held-out share of the top heads
Time
146 min per run (R+K 36 and H 37, per split)

exp5 · next-two conditioning

controlled/exp5_ar_next_two_conditioning

In next-two models, how much does item 2 depend on item 1?

What it does
Clamp item 1 of the target to another catalog item at each shared-prefix level and score item 2; compare with replacing the most recent history item. Patch the residual stream of item 1, the separator and item 2 at every layer.
Runs on
93 AR next-two runs
Output
Item-1 effect on item 2's digits; where item-1 information sits by layer
Time
35 min per run

exp6 · copy reads blocked during decoding

controlled/exp6_ar_copy_in_decoding (run_grid.py)

Does copying help or hurt the final top-10 list, and for which targets?

What it does
Decodes the test cohort with the run's own decoder (constrained beam search, 50 beams, then raw-vocabulary rescoring of every returned SID) four times. B: no edit. C_later: when a beam predicts digit d, block its reads of digit d of history items whose first d digits equal the beam's own prefix (layers 14–27). C_all: C_later plus every first-digit read. N_later: block as many reads of non-matching items. The same edges are blocked in the rescoring pass, because the list is ranked by it.
Runs on
93 AR next-item runs
Output
SID and item Hit@10 and NDCG@10 per condition, overall and by target class (same item, SID partner, near-duplicate variant, new)
Time
70 min per run at plan rates; about 10 h if decoding runs one row at a time

exp9 · list order against review time

controlled/exp9_ar_order_vs_time

Does the model follow the position of the two most recent items, or their review days?

What it does
Swaps the two most recent history items and splits rows by their review days (later day, same day with a later target, same day as the target). Teacher-forced scores for all rows; a decode of the swapped prompts for the decision-level effect. Rows whose review day cannot be settled (one Office event) are left out.
Runs on
93 AR next-item runs
Output
Position and item effects on the first digit; how often the top-1 SID flips; Hit@10 change
Time
34 min per run at plan rates; about 4.7 h if decoding runs one row at a time

exp10 · last digit of a prefix-matching item

controlled/exp10_ar_last_digit_sibling

At the last digit, does reading a matching history item push the model toward that item's code or away from it?

What it does
Removes the edge from the last-digit readout to the last-digit token of the most recent history item that matches the target on all earlier digits, against a control edge; splits rows by whether the target is that item's sibling.
Runs on
93 AR next-item runs, test and validation splits
Output
Log-probability of the item's own code and of the target's code; how often each is top-1
Time
4 min per run

AR: representations (one job per run)

Each AR next-item run gets one job that captures activations to scratch, runs the three experiments, then deletes the captures.

representation exp1 · logit lens and probes

representation/exp1_ar_digit_decoding
What it does
Captures all 28 layers at the history, header and target tokens of the test split. Reads each layer through the model's own unembedding (logit lens) and fits user-disjoint linear probes for the target's digits and the most recent item's first digit.
Output
The layer where the copy preference appears; which digits are linearly present at the readout
Time
≈145 min per run (pilot: 83 min on 64 rows, mostly fixed probe-fitting cost)

representation exp2 · sparse autoencoders

representation/exp2_ar_sae
What it does
Trains TopK SAEs at layers 12, 16, 20 and 24 on train-split captures; finds copy and prefix-match latents on held-out users; ablates them at the readout against matched control latents. Includes the A1 amendment (latents matched by within-digit AUC).
Output
Reconstruction quality; causal effect of copy latents; prefix-match latents and their effect
Time
≈100 min per run

representation exp3 · information map

representation/exp3_ar_information_map
What it does
Captures with the model's own greedy answer in the target slot; trains SAEs at every second layer; labels every latent (census); fits a tuned lens and SID decoders per layer.
Output
What each layer's latents encode; the layer from which the answer is fixed
Time
≈125 min per run

DiffGRM

exp1 and exp2 · reveal orders at equal beams

controlled/exp1_matched_beam, exp2_fixed_orders
What it does
exp1 decodes with confidence-ordered reveals and with one fixed order at beams 64 and 256. exp2 runs all six fixed orders on depth-3 maps. On the grid both add the run's own search (left to right, catalog-legal codes at every step) as a condition.
Runs on
93 DiffGRM next-item runs (exp2: the 31 depth-3 maps)
Output
SID and item Hit@10 per reveal policy and the paired differences

exp7, exp8, exp12 · how DiffGRM uses the history

controlled/exp7, exp8, exp12
What it does
exp7 replaces history items and knocks out cross-attention edges, as exp3/exp4 do for AR. exp8 separates the encoder route (other slots reading the most recent item) from the direct decoder read. exp12 patches encoder slots, decoder residuals and cross-attention outputs between paired runs. All three score states without decoding and run on CPU.
Runs on
93 DiffGRM next-item runs; exp7 also at every DiffGRM snapshot

exp13, exp14 · interventions held through decoding

controlled/exp13, exp14
What it does
exp13 replaces the most recent item only at chosen reveal steps (on the grid, step t reveals digit t). exp14 blocks the copy route for the whole decode, swaps the two most recent items, and shifts the history by 1 or 5 slots. Both use the run's own decoder.
Output
Which steps decide the top-1; Hit@10 change by target class

representation exp4, exp5 · reveal trace and encoder features

representation/exp4, exp5
What it does
exp4 records what the decoder holds at every reveal step and block. exp5 fits probes and SAEs on the encoder and a description autoencoder.
Time
exp1, exp13, exp14, rep4, rep5, N1, N3 together: ≈51 min per DiffGRM run

Saved test lists (CPU)

retrospective exp2, exp3, exp4, exp6, exp7

python -m sidlens.grid.saved_lists
What it does
Recomputes the earlier audits from each run's saved lists. exp2: the first wrong digit of the top-1. exp3: SID-level hits against item-level bounds, collided against singleton targets. exp4: in next-two lists, P(item 2 right | item 1 right) against P(item 2 right | item 1 wrong). exp6: hits and the top-1's copy of the most recent item's first code by review-day gap. exp7: exp6's conditions re-scored at item level by target class.
Runs on
All 372 runs (exp4: the 186 next-two runs; exp7: the 93 AR next-item runs)
Time
seconds to a few minutes per run

New experiments (protocols written before any result)

N1 · prefix conditioning

additions/n1_prefix_conditioning

Does the copy need the item's whole prefix to match, or only the digit just before it, as a plain induction head would?

What it does
For each row and digit d ≥ 2, take the most recent history item h whose first d digits equal the target's. Replace h with an item that keeps only digits d−1 and d (suffix), one that keeps neither (none), or one that keeps the prefix but changes digit d (prefix). Score digit d at the golden prefix.
Runs on
93 AR and 93 DiffGRM next-item runs
Primary result
ρ = support(suffix) / support(full). Near 0 means prefix-conditioned copying; near 1 means last-token copying.
Time
15 min per AR run

N2 · how the AR model matches the prefix

additions/n2_ar_prefix_match
What it does
On N1's rows: (a) attention to h's digit token per head; (b) replace only the key, or only the value, at that token in layers 14–27 with the suffix run's; (c) block, in layers 0–13, h's digit token from reading h's earlier digits; (d) take the query from a run whose prefix matches another item and see whether attention follows; (e) each late head's direct contribution to the copied code; (f) induction scores of the base Qwen2.5-1.5B-Instruct heads against each run's head screen from exp4.
Primary result
The share of the copy removed by the key replacement and by the value replacement
Time
50 min per run; (f) about 1 GPU-hour once

N3 · copy dose-response

additions/n3_copy_dose
What it does
Scales the attention weights that exp6 (AR) and exp14 (DiffGRM) block by α ∈ {0, 0.25, 0.5, 1, 1.5, 2} inside the run's own beam search. α = 0 is the block; α = 1 changes nothing and is checked bit for bit.
Primary result
Change in new-target SID Hit@10 at α = 0.5; repeat and new targets at SID and item level
Time
AR 105 min per run at plan rates; about 14.5 h if decoding runs one row at a time

N4 · no-training baselines

additions/n4_no_training_baselines
What it does
Three top-10 lists without a model: a copy rule (history prefix overlap, then recency, then popularity), training popularity, and popularity within the most recent item's first code. Each is compared with the run's saved list.
Primary result
Model minus popularity on new targets; how often the model's top-1 first code equals the copy rule's
Time
under a minute per run (CPU)

Time

Per-run minutes come from the per-part times of our earlier A100 jobs, scaled to 6,297 events per catalog (COPYING_GRID_PLAN.md §5.1), with two corrections: exp4 runs Part H on both splits, and the representation experiments run as one GPU job per model, so their CPU stages hold the GPU.

The main uncertainty is AR decoding. The grid evaluates AR models with 50 beams, one row at a time, then rescores up to 50 candidate SIDs one at a time. Our decoder does the same, because V2a requires it to reproduce the saved lists. If a row takes about 1.4 s on an A100 (≈0.15 s of search and ≈1.25 s of rescoring), one decode of 6,297 rows takes about 2.4 h, and exp6, exp9 and N3 cost about 2,700 GPU-hours instead of 325. The pilot measures this directly. If it holds, the cheapest fix is to rescore each row's candidates in one batch for the intervention conditions; all conditions would still go through the same route, and V2b already reports any difference from the plain decoder.
